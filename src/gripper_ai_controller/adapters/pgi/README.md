# PGI TCP 夹爪适配器

本包封装项目原始资料中 PGI socket 示例使用的 14 字节 TCP 寄存器协议。实现仅依赖 Python 标准库，并将连接、协议校验和未来的网页人工控制与厂商示例中的全局 socket 隔离。

## 已验证能力

- 建立和关闭一个实例私有的 TCP 连接；
- 读取初始化状态、夹持状态和已设定目标位置；
- 发送普通初始化请求；
- 设置目标力和目标位置。

当前协议资料没有证明 TCP 网关的速度寄存器，也没有提供可靠的软件停止语义。因此本包不会提供速度写入、`STOP`、`HOLD` 或 `0xA5` 全行程重新标定。上层不得把“锁定网页控制”描述为物理急停；设备运动期间必须依赖现场独立急停和安全操作规程。

## 生命周期

`PgiTcpGripperAdapter.startup()` 只尝试连接并读取状态，不执行初始化或运动。连接或状态读取失败时适配器以降级状态启动，以便本机网页提供“重新连接”；真实初始化只能由显式的 `operator_initialize()` 调用触发。通用 `initialize()` 只读取状态，不改变设备。

同步 socket 调用由适配器的单工作线程执行，客户端内部还使用实例级锁保证每个请求与响应不可交错。每次响应都会校验帧头、帧尾、设备 ID、寄存器地址和操作码。厂商示例只规定请求帧的第 8、11、12 字节固定为 `0x00`，没有定义响应中这三个保留字节的语义，因此当前不会把响应保留字节错误地视为固定常量。读取操作在接收不完整、超时或协议不匹配后会关闭当前 socket，并在有限次数内重新连接重试；写操作一旦开始发送，任何传输或响应故障都会报告“结果不确定”并断开连接，绝不自动重发。

当前项目内的 TCP 示例把 `0x0602` 命名为当前位置，但该寄存器在 PGI 手册中属于目标设定位置。本适配器因此只将它公开为“已设定目标位置”，不会将其表述为实时物理位置反馈。实时反馈寄存器的 TCP 映射尚未在本项目资料中验证，不能据此实现或展示。

真实主机、端口和设备 ID 必须放在被 Git 忽略的 `localstore/` 配置中。自动化测试只能注入假 socket，不得连接物理夹爪。
